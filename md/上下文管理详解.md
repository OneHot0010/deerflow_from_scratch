# tob_audit_agent（Aegis）上下文管理详解

> 本文结合源码，详细解析 tob_audit_agent-master（内部代号 **Aegis**，基于 LangChain / LangGraph 构建）的“上下文管理”实现。
>
> 上下文管理并非单一模块，而是由 **四层机制** 协同构成：
>
> 1. **持久化层** —— Checkpointer 将对话状态跨调用落盘
> 2. **状态建模层** —— ThreadState 定义在中间件间流转的结构化状态
> 3. **中间件流水线层** —— 18 个 Middleware 在请求生命周期内压缩/修复/保护上下文（主战场）
> 4. **工具输出截断层** —— 在工具返回时就控制体积，从源头减负
>
> 核心目标：在长对话、工具密集的审计任务中，既不撑爆模型 token 窗口，又不丢失关键信息（技能加载、待办、上传文件等）。

---

## 一、持久化层：Checkpointer（对话状态落盘）

**文件**：`backend/packages/harness/aegis/agents/checkpointer/provider.py`

Checkpointer 是 LangGraph 的状态存储组件，负责把每个 thread 的完整状态跨调用保存下来，是“上下文”能够连续的基础。

### 支持的后端

```python
if config.type == "memory":
    from langgraph.checkpoint.memory import InMemorySaver
    yield InMemorySaver()          # 进程内，不持久
...
if config.type == "sqlite":
    from langgraph.checkpoint.sqlite import SqliteSaver
    conn_str = resolve_sqlite_conn_str(config.connection_string or "store.db")
    ensure_sqlite_parent_dir(conn_str)
    with SqliteSaver.from_conn_string(conn_str) as saver:
        saver.setup()              # 单进程文件
        yield saver
...
if config.type == "postgres":
    from langgraph.checkpoint.postgres import PostgresSaver
    ...                            # 生产多进程
```

- **memory**：进程内，不持久化
- **sqlite**：单进程文件（`config.yaml` 实际采用，连接串 `checkpoints.db`）
- **postgres**：生产环境多进程

### 双模式生命周期

```python
# 单例：复用连接，进程退出时关闭
def get_checkpointer() -> Checkpointer:
    global _checkpointer, _checkpointer_ctx
    if _checkpointer is not None:
        return _checkpointer
    ...
    if config is None:
        _checkpointer = InMemorySaver()   # 未配置时兜底
        return _checkpointer
    _checkpointer_ctx = _sync_checkpointer_cm(config)
    _checkpointer = _checkpointer_ctx.__enter__()
    return _checkpointer

# 上下文管理器：每次新建 / 销毁连接，供 CLI 与测试用
@contextlib.contextmanager
def checkpointer_context() -> Iterator[Checkpointer]:
    ...
```

**要点**：
- 单例复用连接、`reset_checkpointer()` 可强制重建（测试或配置变更后）。
- 未配置时统一回退为 `InMemorySaver`。
- `config.yaml` 中实际配置：

```yaml
checkpointer:
  type: sqlite
  connection_string: checkpoints.db
```

## 二、状态建模层：ThreadState

**文件**：`backend/packages/harness/aegis/agents/thread_state.py`

`ThreadState` 继承自 LangChain `AgentState`，定义了在中间件间流转的上下文状态结构：

```python
class ThreadState(AgentState):
    sandbox: NotRequired[SandboxState | None]
    thread_data: NotRequired[ThreadDataState | None]
    title: NotRequired[str | None]
    artifacts: Annotated[list[str], merge_artifacts]
    todos: NotRequired[list | None]
    uploaded_files: NotRequired[list[dict] | None]
    viewed_images: Annotated[dict[str, ViewedImageData], merge_viewed_images]
```

关键字段：

| 字段 | 作用 |
|------|------|
| `messages`（继承自 AgentState） | 对话消息主体，上下文窗口的核心 |
| `sandbox` / `thread_data` | 沙箱实例与线程隔离目录（`workspace/`、`uploads/`、`outputs/`） |
| `todos` | 待办列表 |
| `title` | 线程标题 |
| `uploaded_files` | 上传文件元数据 |
| `artifacts` / `viewed_images` | 产物与已查看图像，带自定义 reducer |

### 自定义 Reducer（合并策略）

```python
def merge_artifacts(existing, new) -> list[str]:
    # 合并并按顺序去重
    return list(dict.fromkeys(existing + new))

def merge_viewed_images(existing, new) -> dict[str, ViewedImageData]:
    # 特殊：new 为空 dict {} 时，清空所有已查看图像
    if len(new) == 0:
        return {}
    return {**existing, **new}
```

`merge_viewed_images` 支持用空 dict `{}` 主动清空——供中间件处理完图像后**释放上下文占用**，这是精细化控制 token 的一个设计点。

## 三、中间件流水线层（上下文管理主战场）

**文档**：`docs/backend/MIDDLEWARES.md`
**组装位置**：`lead_agent/agent.py` 的 `_build_middlewares()`

Aegis 使用 LangChain 的 `AgentMiddleware` 系统，18 个中间件按严格顺序处理请求生命周期。排序约束（源码注释）：

> - ThreadData 在 Sandbox 之前（需要 thread_id）
> - Uploads 在 ThreadData 之后
> - DanglingToolCall 在模型看到历史之前
> - **Summarization 尽早执行**（在其他处理前减少上下文）
> - TodoList 在 Clarification 之前
> - Clarification **永远最后**

下面详解与上下文管理直接相关的中间件。

### 3.1 SummarizationMiddleware —— 核心压缩机制

**文件**：`agents/middlewares/summarization_middleware.py`
**类**：`AegisSummarizationMiddleware`（继承 LangChain `SummarizationMiddleware`）

在 `before_model` 阶段、其他处理之前运行，以尽早缩减上下文。

#### 主流程

```python
def _maybe_summarize(self, state, runtime) -> dict | None:
    messages = state["messages"]
    self._ensure_message_ids(messages)

    total_tokens = self.token_counter(messages)
    if not self._should_summarize(messages, total_tokens):
        return None                          # 未达阈值，不动作

    cutoff_index = self._determine_cutoff_index(messages)
    if cutoff_index <= 0:
        return None

    # 分区：待总结 vs 保留（含技能救援）
    messages_to_summarize, preserved_messages = \
        self._partition_with_skill_rescue(messages, cutoff_index)
    self._fire_hooks(messages_to_summarize, preserved_messages, runtime)
    summary = self._create_summary(messages_to_summarize)
    new_messages = self._build_new_messages(summary)

    return {
        "messages": [
            RemoveMessage(id=REMOVE_ALL_MESSAGES),  # 清空全部
            *new_messages,                          # 摘要
            *preserved_messages,                    # 保留的近期消息
        ]
    }
```

流程：统计 token → 达阈值 → 计算切分点 → 分区 → 触发钩子 → LLM 生成摘要 → 用 `RemoveMessage(REMOVE_ALL_MESSAGES)` 清空后重建为「摘要 + 保留消息」。

#### 改造点一：技能救援（Skill Rescue）

Aegis 是技能密集型 Agent，总结时若把“刚学会的技能文件”压掉会导致“遗忘技能”。因此 `_partition_with_skill_rescue` 会识别读取技能目录文件的 `AIMessage + ToolMessage` 配对，并按预算保留最近加载的技能。

```python
def _is_skill_tool_call(self, tool_call, skills_root) -> bool:
    name = tool_call.get("name") or ""
    if name not in self._skill_file_read_tool_names:   # read_file/read/view/cat
        return False
    path = _tool_call_path(tool_call)
    if not path:
        return False
    roots = {skills_root.rstrip("/")}
    if skills_root.startswith("$HOME/"):
        roots.add("/home/tiger/" + skills_root.removeprefix("$HOME/").rstrip("/"))
    for root in roots:
        if path == root or path.startswith(root + "/"):
            return True
    return False
```

选择策略：**由新到旧、按 skill_key 去重、受多重预算约束**：

```python
def _select_bundles_to_rescue(self, bundles) -> list[_SkillBundle]:
    seen_skill_keys, total_tokens, kept = set(), 0, 0
    for bundle in reversed(bundles):                  # 最新优先
        if kept >= self._preserve_recent_skill_count:            # 数量上限
            break
        if bundle.skill_key in seen_skill_keys:                  # 去重
            continue
        if bundle.skill_tool_tokens > self._preserve_recent_skill_tokens_per_skill:  # 单技能上限
            continue
        if total_tokens + bundle.skill_tool_tokens > self._preserve_recent_skill_tokens:  # 总预算
            continue
        selected.append(bundle); total_tokens += bundle.skill_tool_tokens
        kept += 1; seen_skill_keys.add(bundle.skill_key)
    ...
```

默认预算：最多 **5 个**（`preserve_recent_skill_count`）、总计 **25000 token**（`preserve_recent_skill_tokens`）、单技能上限 **5000 token**（`preserve_recent_skill_tokens_per_skill`）。

#### 改造点二：防失忆的 trim 重写

基类 `_trim_messages_for_summary` 强制 `start_on="human"`。但 Aegis 的系统提示是在模型调用时才注入的（由 `OwnerSkillsMiddleware`），待总结切片里没有 `SystemMessage`，且工具密集尾部常不以 `HumanMessage` 开头——基类会 trim 出空列表，回退到 “Previous conversation was too long to summarize.”，**整段历史被丢弃（失忆）**。

```python
def _trim_messages_for_summary(self, messages):
    if self.trim_tokens_to_summarize is None:
        return messages
    try:
        trimmed = trim_messages(
            messages,
            max_tokens=self.trim_tokens_to_summarize,
            token_counter=self.token_counter,
            strategy="last",
            allow_partial=True,
            include_system=True,          # 去掉了 start_on="human"
        )
    except Exception:
        return messages[-_DEFAULT_FALLBACK_MESSAGE_COUNT:]
    if not trimmed:
        # 保证：非空输入永不被 trim 成空
        return messages[-_DEFAULT_FALLBACK_MESSAGE_COUNT:]
    return trimmed
```

**要点**：保留 token 预算上限，但去掉人类锚点要求，并保证非空输入永不被 trim 成空（必要时回退到最近消息切片）。

#### 配置（summarization_config.py + config.yaml，当前 enabled: true）

```yaml
summarization:
  enabled: true
  model_name: null          # null → 用轻量模型做总结以省成本
  trigger:
    - type: tokens
      value: 15564          # token 达到 15564 触发（也支持 messages / fraction，OR 逻辑）
  keep:
    type: messages
    value: 10               # 保留最近 10 条消息
```

`trim_tokens_to_summarize` 默认 4000。

### 3.2 TodoMiddleware —— 上下文丢失检测与防提前退出

**文件**：`agents/middlewares/todo_middleware.py`（扩展 `TodoListMiddleware`）

专门应对“总结把待办滚出窗口”的问题。

#### before_model：待办丢失检测

```python
def before_model(self, state, runtime):
    todos = state.get("todos") or []
    if not todos:
        return None
    messages = state.get("messages") or []
    if _todos_in_messages(messages):   # write_todos 仍可见 → 无需处理
        return None
    if _reminder_in_messages(messages):  # 已注入过提醒
        return None
    # 待办在 state 里，但 write_todos 调用已被总结移除 → 重新贴回
    formatted = _format_todos(todos)
    reminder = HumanMessage(
        name="todo_reminder",
        content=("<system_reminder>\n"
                 "Your todo list from earlier is no longer visible ... but it is still active:\n\n"
                 f"{formatted}\n\n"
                 "Continue tracking and updating this todo list ...\n"
                 "</system_reminder>"),
    )
    return {"messages": [reminder]}
```

#### after_model：防止未完成时提前退出

```python
_MAX_COMPLETION_REMINDERS = 2   # 防死循环

@hook_config(can_jump_to=["model"])
def after_model(self, state, runtime):
    base_result = super().after_model(state, runtime)
    if base_result is not None:
        return base_result
    messages = state.get("messages") or []
    last_ai = next((m for m in reversed(messages) if isinstance(m, AIMessage)), None)
    if not last_ai or last_ai.tool_calls:      # 模型仍在调用工具，不干预
        return None
    todos = state.get("todos") or []
    if not todos or all(t.get("status") == "completed" for t in todos):
        return None                            # 全部完成，允许退出
    if _completion_reminder_count(messages) >= self._MAX_COMPLETION_REMINDERS:
        return None                            # 达到提醒上限，避免死循环
    # 注入提醒 + 强制回到模型继续
    reminder = HumanMessage(name="todo_completion_reminder", content="...")
    return {"jump_to": "model", "messages": [reminder]}
```

### 3.3 其它辅助上下文的中间件

| 中间件 | 上下文相关作用 |
|--------|----------------|
| **UploadsMiddleware** | 把上传文件元数据与文档大纲以 `<uploaded_files>` 块前置进用户消息 |
| **DanglingToolCallMiddleware** | 用户中断时，给缺失 `ToolMessage` 的 tool_calls 注入占位错误消息，保证消息序列合法（否则模型无法消费历史） |
| **ViewImageMiddleware** | 视觉模型下，`view_image` 完成后把 base64 图像塞进 `HumanMessage`，配合 `viewed_images` 的可清空 reducer 控制占用 |
| **DeferredToolFilterMiddleware** | `tool_search` 开启时，从请求里移除延迟加载的 MCP 工具 schema（**节省上下文**），模型通过 `tool_search` 按需“提升” |
| **LoopDetectionMiddleware** | 哈希/频率双层检测，打断重复工具调用，避免无意义污染上下文 |
| **TokenUsageMiddleware** | 记录 input/output/total token 消耗 |
| **TitleMiddleware** | 首次完整对话后生成线程标题 |
| **MemoryMiddleware** | 把 user + final AI 消息入防抖队列（30s）做长期记忆事实提取 |

## 四、工具输出截断层（源头减负）

**文件**：`sandbox/tools.py` + `config/sandbox_config.py`

在工具**返回结果时**就限制体积，避免超长输出直接灌入上下文。

### bash 输出：中间截断（保留头尾各半）

```python
def _truncate_bash_output(output: str, max_chars: int) -> str:
    if max_chars == 0:
        return output
    if len(output) <= max_chars:
        return output
    total_len = len(output)
    marker_max_len = len(f"\n... [middle truncated: {total_len} chars skipped] ...\n")
    kept = max(0, max_chars - marker_max_len)
    if kept == 0:
        return output[:max_chars]
    head_len = kept // 2
    tail_len = kept - head_len
    skipped = total_len - kept
    marker = f"\n... [middle truncated: {skipped} chars skipped] ...\n"
    return f"{output[:head_len]}{marker}{output[-tail_len:] if tail_len > 0 else ''}"
```

> bash 的 stderr/stdout 顺序不确定，两端都可能有错误信息，故头尾各保留一半。

### read_file 输出：头部截断

```python
def _truncate_read_file_output(output: str, max_chars: int) -> str:
    ...
    marker = f"\n... [truncated: showing first {kept} of {total} chars. Use start_line/end_line to read a specific range] ..."
    return f"{output[:kept]}{marker}"
```

> 源码/文档从头往下读，头部信息量最大（imports、类定义、函数签名），故保留开头。

### 配置（sandbox_config.py）

| 参数 | 默认值 | 截断方式 |
|------|--------|----------|
| `bash_output_max_chars` | 20000 | 中间截断（头尾各半） |
| `read_file_output_max_chars` | 50000 | 头部截断 |
| `ls_output_max_chars` | 20000 | 头部截断 |

均可设 `0` 关闭。此外 glob/grep 结果超限也会标记 “Results truncated”。

## 五、总结：一次请求中的上下文处理链路

```
Checkpointer 载入 ThreadState（messages / todos / ...）
   → DanglingToolCall 修复中断的工具调用
   → Summarization 判断 token（>15564）
        → 总结旧消息、救援最近技能、保留最近 10 条
   → Todo 检测待办是否被滚出 → 必要时注入提醒
   → （DeferredToolFilter 隐藏延迟工具 schema 省上下文）
   → 模型调用
   → 工具执行时按 max_chars 截断输出
   → Checkpointer 落盘，供下轮延续
```

**一句话概括**：

> Aegis 的上下文管理 = **Checkpointer 做持久化底座** + **ThreadState 做结构化状态** + **Summarization / Todo 等中间件在 token 逼近阈值时“智能压缩而不失忆”** + **工具层前置截断从源头控制体积**。

其中最有特色的是总结时对“最近加载技能”和“活跃待办”的**双重救援机制**，专为工具/技能密集的审计 Agent 场景设计。
